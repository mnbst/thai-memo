# 聞き流し再生とサーバー音声の設計

## 目的

競合「タイ語キキタイ」（YUUUM、2026-09 公開）は「聴く」に特化し、通勤・家事中の
聞き流しと講師の声で評価されている。こちらは能動学習（分解・クイズ・発音採点）が軸だが、
「毎日タイ語の音を浴びる」導線が無い。

1. 自分で例文を集めた**トラック**を作り、順に流す**聞き流し再生**を足す（アプリを裏に回しても、画面ロック中も鳴り続ける）
2. 端末TTSをやめ、**Cloud TTS（Chirp3-HD）で作った音声**に置き換える。
   例文詳細の再生と聞き流しは同じ音声ファイルを使う

本ドキュメントは設計段階のもの。実装は未着手。

## 決定事項

| 項目 | 決定 |
|---|---|
| 入口 | 履歴タブの「トラック」。**ユーザーが作ったトラック**を選んで上から流す（2026-10-19 に一覧の絞り込み再生から変更） |
| トラック | 名前付きの例文の並び。履歴・例文詳細から追加し、並べ替え・削除できる。1トラック100文まで |
| 1文の流れ | さらっと：全文 → 訳 → 全文 ／ じっくり：全文 → (単語 → 意味)×n → 訳 → 全文 |
| 音声の出どころ | Cloud TTS Chirp3-HD。サーバーで作り Storage に置く |
| 再生 | `just_audio` のプレイリスト（部品ごとのファイル＋無音）＋ `audio_service` |
| 声 | タイ語は男女をルールで出し分け。日英（意味・訳）は性別に関係なく固定の案内役1声 |
| ゆっくり | 再生側の `setSpeed` で遅くする。別ファイルは作らない。0.7倍までは自然に聞こえる（2026-10-21 聴き比べで決定） |
| ファイル名 | 部品ごとに**中身のハッシュ**。例文IDでは紐付けない |
| 端末保持 | いずれかのトラックに入っている例文の音声を端末に保持。それ以外は一時キャッシュ |
| 課金 | Premium 機能。無料は**トラック1つ・5文まで** |
| 端末TTS | 生成直後でサーバー音声がまだ無い数秒間と、取得に失敗したときの予備だけ |
| 作成の上限 | callable で新しく作るのは1人1日100文まで（作成済みを返すのは数えない）。文はクライアントが送るので、作らせ続けられないようにする |
| 音声の渡し方 | callable `getSentenceAudio` が MP3 のバイト列をそのまま返す（1文 7〜20KB）。URL を渡さないのでバケット `<project>-tts-audio` は非公開（2026-10-21） |
| 先に作るか | 作らない。どの環境も再生されたときに callable が作る。最初に聞く人だけ 1〜2 秒ローディングで待つ（2026-10-21） |
| 最初の実装範囲 | お手本の全文（詳細の再生・発音練習シート）。単語タップ・クイズ・聞き流しは端末TTSのまま |

## 音声の部品

1文あたり、サーバーで次を作る。

| 部品 | 中身 | 使う場所 |
|---|---|---|
| 全文 | `thai_text` | 詳細の再生・お手本・聞き流し |
| 単語 | `word_breakdowns[i].word_text` | 単語タップ・聞き流し |
| 意味 | `word_breakdowns[i].meaning`（括弧内の注記は落とす） | 聞き流し |
| 訳 | `japanese_translation`（アプリ言語の訳。英語版なら英訳） | 聞き流し |

`manifest` は持たない。クライアントは例文の中身から各部品のファイル名を計算する（次節）。

### ファイル名（中身のハッシュ）

```
audio/{sha256(voice_config_version | voice_name | speaking_rate | text)}.mp3
```

- 声の選び方も例文の中身から決まる（次節）ので、**履歴に残った例文の中身だけ**で
  いつでも同じファイル名を計算し直せる。プールの元文とは紐付けない
- プールから文を手作業で消しても、音声側の作業は不要。配布済みの履歴はそのまま鳴る
- 訳や語義を手で直すと、直した部品だけファイル名が変わり、次に要求されたときに作られる
- 同じ単語・同じ語義は全例文で1ファイルを共有する（ไป・ครับ などは1回作れば済む）
- 古いファイルは消さない。静的コーパス1.3万文を全部作っても1GB前後で、保管料は月$0.02/GB程度
- 声の設定を変えると全ファイル名が変わる。`voice_config_version` を上げるときだけ意図して変える

### 生成のきっかけ

音声取得用の callable `getSentenceAudio` を1つ置く。例文の中身を受け取り、ファイル名を計算し、
**無いときだけ作って**音声を返す。**先には作らない**（2026-10-21 決定）。一括生成も、プールへ足すときの生成もしない。

- 作るのは再生されたときだけ。一度も聞かれない文の音声を作らずに済み、Cloud TTS の1分あたりの割り当て
  （dev で同時8本流すと大半が 429 で弾かれた）や月の無料枠（100万文字）も気にしなくてよい
- 最初に聞く1人だけ 1〜2 秒待つ。そのあいだは再生ボタンにローディングを出す（0.3 秒より早く鳴るなら出さない）
- 取得に失敗した・6秒待っても届かないときは、端末TTS（`TtsService`）で読む

### プールへの追加（目視確認を挟む）

今は dailyBatch のステップ6（`poolAccepted`）が、judge を通った文をそのまま本番プール
（`corpus_pool_<lang>.json` / `free_pool_<lang>.json`）へ足している。これを、人が見て OK した文だけ足す形に変える
（2026-10-21 決定）。

1. dailyBatch は judge を通った文を、本番プールではなく Firestore の**確認待ち**に入れる
2. 確認待ちの文を、Claude が Artifact ページに並べる（タイ語・発音・訳・単語分解・テーマ・judge の所見）。
   人が文ごとに OK / NG を付ける
3. Claude がページの結果を読み、OK の文だけを本番プールへ足す（`cmd/poolreview apply`）。NG は `rejected` にする（消さない）
4. 2〜3 はスキル `pool-review` にまとめる（`fw-trans-audit` などと同じ、プールを見る運用の1つ）

- 確認待ちの置き場は Firestore（1文1 doc。状態を文ごとに書き換えるので、GCS の JSON 1本より扱いやすい）。
  doc ID は ティア・言語・`thai_text` のハッシュにし、同じプールへ同じ文を二重に入れない
  （同じタイ語でも日英・free/premium で訳と振り分けが違うので、別々に確認する）
- 確認するまで本番プールには入らないので、プールの増え方は確認の頻度で決まる
- 確認待ちは**期限なしで保持**する。OK / NG を付けるまで消さない

#### 確認待ちの doc の項目

例文を生成したときの中身を、本番プールの1件（`sentence.Sentence`）と同じ形で**全部**持つ。
OK のときはそのまま本番プールへ移せるようにする。

| 項目 | 中身 |
|---|---|
| 例文 | `thai_text`・`pronunciation`・訳（`japanese_translation`。英語版は英訳）・`key_word`・`generation_tier` |
| 単語分解 | `word_breakdown`（語・意味・注記・音節・発音・品詞） |
| 背景 | `context`（`topic`・`subTheme`・`style`・`emotion`・`usage_scenarios`・`cultural_notes`） |
| 振り分け | `tier`（premium / free）・`lang` |
| 判定 | judge の結果と所見 |
| 出どころ | 元の例文 doc の参照・生成日時 |
| 状態 | `pending` / `approved` / `rejected`、確認した日時 |

NG の文も状態を `rejected` にして残す（同じ文がまた生成されたときに、確認待ちへ入れ直さないため）

## 声の選び方

### タイ語：男女をルールで出し分け

上から見て最初に当たったもので決める。

| 順 | 手がかり | 男性 | 女性 |
|---|---|---|---|
| 1 | 文末の丁寧語 | ครับ・คับ | ค่ะ・คะ・คร่ะ |
| 2 | 一人称代名詞 | ผม・กระผม | ดิฉัน・หนู（自称） |
| 3 | テーマが BL ドラマ（`topic` に「BL」を含む） | 男性 | ― |
| 4 | どれも無い | `thai_text` のハッシュで決める（同じ文は常に同じ声） | |

- ฉัน・เรา は男女とも使うので手がかりにしない
- ผม は「髪」もあるので文字列一致では見ない。`word_breakdowns` の代名詞（品詞または語義が「私」）に限る。
  ครับ・ค่ะ は紛れないので文字列一致でよい
- 男女の手がかりが両方ある文（引用など）は文末を優先する
- BL は文末・一人称の後に見る。dev プールの BL 1,409文のうち文末が ค่ะ・คะ なのは1文（女性の脇役）だけなので、
  それは女性のまま残す。`topic` の無い古い履歴はハッシュに落ちる
- 同じ性別の中でどの声にするかは `thai_text` のハッシュで決める。**ランダムに選ばない**
  （選ぶたびにファイル名が変わるため）
- ルールや声の表を変えると声が変わる文が出る。そのときは `voice_config_version` を上げる
- 単語の部品もその文の話者と同じ声にする
- 判定はサーバー（`internal/ttsaudio`）だけに置く。端末は文の中身（全文・テーマ・単語分解）を送り、
  保存は全文のハッシュで持つので、声を知らなくてよい
- dev プール 13,374文では、文末で決まる 29%・一人称 7%・BL 9%・ハッシュ 55%
- Jev（話者は男性か）も試したが、手がかりの無い文は 0.41〜0.52 で決まらなかった（2026-10-21、10文）。使わない

### 日英：案内役の固定1声

意味・訳は性別に関係なく固定の1声（ja-JP / en-US の Chirp3-HD）。タイ語の話者と声が違うので
「いまは解説」と耳で区別できる。

## 詳細画面の再生

今の `SentenceAudioPlayer` は、頭出しバーで選んだ単語から後ろの文字列を TTS に読み直させている。
時刻は使っておらず、バーの位置は「文字位置 ÷ 全体の文字数」で出している（`wordIndexAtProgress`）。

ファイルにしても同じ考え方をとる。文字の割合 ≒ 時間の割合とみなし、
**頭出し位置 = 単語の先頭の文字位置 ÷ 全体の文字数 × 音声の長さ**。
精度は今と同程度の見込み。ずれが気になれば、単語ファイルの長さの比で割り振る。

Chirp3-HD は SSML の `<mark>` に対する timepoints を返さない（実測で空）。Neural2 は返すが
タイ語は女性1声だけで男女の出し分けができないため採らない。

- 単語タップは、その単語のファイルを鳴らす
- 毎回声をランダムに選ぶ今の挙動（`_pickRandomVoice`）は無くなり、文ごとに声が決まる
- 「ゆっくり」は全文のファイルを `setSpeed(0.7)` で鳴らす。0.5倍は不自然なので下限は0.7倍

## 端末への保持

| 例文 | 扱い |
|---|---|
| トラックに入っている | 端末に保持。オフラインで再生できる |
| それ以外 | 再生時に取得し、一時キャッシュ（上限20MB程度、古い順に消す） |

- トラックに追加したら音声一式（約70KB）を落として保持する。一時キャッシュにあれば移すだけ
- どのトラックからも外れたら一時キャッシュ側へ戻す
- 100文のトラックで約7MB。保持の合計は設定画面に出す
- 最初の実装（お手本の全文だけ）は `Application Support/sentence_audio/` に置き、合計 30MB（約2,000文）を超えたら
  最後に聞いたのが古い順に消す（聞くたびに更新日時を付け直し、新しく保存したときに掃除）。
  トラックを入れるときは、トラックに入った文をこの掃除から外す

## バックグラウンド再生

ファイルを `just_audio` で鳴らすので、裏に回しても・画面ロック中も鳴り続け、
ロック画面・イヤホンで操作できる（再生／一時停止・前／次の文）。部品間の無音も再生として扱われる。

- iOS：`UIBackgroundModes` に `audio`
- Android：メディア再生のフォアグラウンドサービス（`FOREGROUND_SERVICE_MEDIA_PLAYBACK`）。Play Console で申告
- 次の文が取得できず音が途切れると、iOS はアプリを止めて取得も止まる。先読みを2〜3文にし、
  間に合わない文は飛ばす
- 裏では、サーバー音声がある文だけを流す（端末TTSでの書き出しが裏で動くかは未検証）
- 割り込み：電話・他アプリの音・イヤホンを抜く → 一時停止。アプリ内でお手本再生や
  発音練習（録音）を始めたら聞き流しを一時停止（iOS の AVAudioSession を共有しているため）

## 通信量

Chirp3-HD の MP3 は 32kbps（約4KB/秒）。

| 部品 | 大きさ |
|---|---|
| 全文 | 約8KB |
| 単語6語前後 | 約25KB |
| 意味6語前後 | 約25KB |
| 訳 | 約8KB |
| **1文合計** | **約70KB**（1セット5文で約350KB、毎日1セット×30日で約11MB） |

## 配信

当面は GCS から直接配信する。CDN は置かない（2026-10-19 決定）。

- 1ユーザー月11〜63MB（毎日1セット〜毎日30文）。1,000人で月11〜63GB、GCS（アジア）の下り転送料で月$2〜10程度
- 同じ部品は全ユーザーで共有し、端末にもキャッシュされるので、実際はこれより減る
- Cloud CDN はロードバランサだけで月$18前後かかり、この規模では割高
- 下り転送料が月数十ドルを超えたら、音声だけ Cloudflare R2（下り転送料なし）へ移す
- ファイル名は中身のハッシュで、同じ名前の中身は変わらない。`Cache-Control: public, max-age=31536000, immutable` を付ける
- URL は callable が返す。クライアントは配信元を持たないので、R2 や CDN に移してもアプリ更新は不要

## 検証済みのこと（端末TTSの予備経路）

`flutter_tts` の `synthesizeToFile`（2026-10-19）。

| | iOS シミュレータ | Android エミュレータ（Google TTS） |
|---|---|---|
| 書き出し | タイ語・日本語・英語すべて成功（.caf / .wav） | すべて成功 |
| 形式 | 22.05kHz・Float32・モノラル | 16bit・モノラル。ネット経由の声48kHz、端末内の声24kHz |
| 速さ | 初回3.6秒、以降20〜240ms/部品 | 初回3.3秒、以降10〜450ms/部品 |
| 機内モード | ― | ネット経由の声は待たずに同じ話者の端末内版へ切り替わる |

- サンプルレートは端末内でも混在する。**部品を1ファイルに結合せず**プレイリストに並べるので変換は不要
- Android は `isFullPath: true` を必ず付ける（付けないと共有の Music フォルダに書く）
- iOS は書き出しと発話が同じシンセサイザーを使うので、お手本再生中は書き出せない
- Android の声は `network_required == "0"` に絞る（遅いネットでの待ちを避ける）。
  項目が無いエンジンは端末内扱い。iOS には項目が無いので全部残る
- 未確認：iOS 実機（高品質な声）、遅いネットでの Android、裏での書き出し

## 未決・要確認

- Chirp3-HD の具体的な声（男性・女性・日英の案内役）の選定。サンプルは聞き比べ用に作成済み
- 年代（若い・大人・年配）での出し分けは当面しない（2026-10-21）。やるなら30声を耳で年代に分け、
