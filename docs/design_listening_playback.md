# 聞き流し再生とサーバー音声の設計

## 目的

競合「タイ語キキタイ」（YUUUM、2026-09 公開）は「聴く」に特化し、通勤・家事中の
聞き流しと講師の声で評価されている。こちらは能動学習（分解・クイズ・発音採点）が軸だが、
「毎日タイ語の音を浴びる」導線が無い。

1. 履歴の例文を順に流す**聞き流し再生**を足す（アプリを裏に回しても、画面ロック中も鳴り続ける）
2. 端末TTSをやめ、**Cloud TTS（Chirp3-HD）で作った音声**に置き換える。
   例文詳細の再生と聞き流しは同じ音声ファイルを使う

本ドキュメントは設計段階のもの。実装は未着手。

## 決定事項

| 項目 | 決定 |
|---|---|
| 入口 | 履歴タブ。絞り込みチップの右に「聞き流す」。**いま一覧に出ている例文**（すべて／お気に入り／検索結果）を上から流す |
| 1文の流れ | さらっと：全文 → 訳 → 全文 ／ じっくり：全文 → (単語 → 意味)×n → 訳 → 全文 |
| 音声の出どころ | Cloud TTS Chirp3-HD。サーバーで作り Storage に置く |
| 再生 | `just_audio` のプレイリスト（部品ごとのファイル＋無音）＋ `audio_service` |
| 声 | タイ語は男女をルールで出し分け。日英（意味・訳）は性別に関係なく固定の案内役1声 |
| ファイル名 | 部品ごとに**中身のハッシュ**。例文IDでは紐付けない |
| 端末保持 | お気に入りの例文だけ音声を端末に保持。それ以外は一時キャッシュ |
| 課金 | Premium 機能。無料は**いま流そうとしている一覧の新しい5文まで** |
| 端末TTS | 生成直後でサーバー音声がまだ無い数秒間と、取得に失敗したときの予備だけ |

## 音声の部品

1文あたり、サーバーで次を作る。

| 部品 | 中身 | 使う場所 |
|---|---|---|
| 全文 | `thai_text` | 詳細の再生・お手本・聞き流し |
| 全文ゆっくり | `thai_text`（`speakingRate` 0.7） | 詳細の「ゆっくり」。押されたときに取りに行く |
| 単語 | `word_breakdowns[i].word_text` | 単語タップ・聞き流し |
| 意味 | `word_breakdowns[i].meaning`（括弧内の注記は落とす） | 聞き流し |
| 訳 | `japanese_translation`（アプリ言語の訳。英語版なら英訳） | 聞き流し |

`manifest` は持たない。クライアントは例文の中身から各部品のファイル名を計算する（次節）。

### ファイル名（中身のハッシュ）

```
audio/{sha256(voice_config_version | voice_name | speaking_rate | text)}.mp3
```

- 声の選び方も例文の中身から決まる（次節）ので、**履歴に残った例文の中身だけ**で
  いつでも同じファイル名を計算し直せる。プールの元文とは紐付けない
- プールから文を手作業で消しても、音声側の作業は不要。配布済みの履歴はそのまま鳴る
- 訳や語義を手で直すと、直した部品だけファイル名が変わり、次に要求されたときに作られる
- 同じ単語・同じ語義は全例文で1ファイルを共有する（ไป・ครับ などは1回作れば済む）
- 古いファイルは消さない。静的コーパス1.3万文を全部作っても1GB前後で、保管料は月$0.02/GB程度
- 声の設定を変えると全ファイル名が変わる。`voice_config_version` を上げるときだけ意図して変える

### 生成のきっかけ

音声取得用の callable を1つ置く。例文の中身を受け取り、部品ごとのファイル名を計算し、
**無いものだけ作って**URLを返す。

- 例文生成・配信の直後にも同じ処理を先に呼び、初回再生の待ちを無くす
- 古い履歴・手で直した文・作り損ねた文も同じ経路で埋まる。専用のバックフィルや再試行は不要
- 生成直後に音声が間に合わない数秒は、端末TTS（今の `TtsService`）で読む。
  同じ文の1回目だけ端末の声になるが許容する

## 声の選び方

### タイ語：男女をルールで出し分け

上から見て最初に当たったもので決める。

| 順 | 手がかり | 男性 | 女性 |
|---|---|---|---|
| 1 | 文末の丁寧語 | ครับ・คับ | ค่ะ・คะ・คร่ะ |
| 2 | 一人称代名詞 | ผม・กระผม | ดิฉัน・หนู（自称） |
| 3 | どちらも無い | `thai_text` のハッシュで決める（同じ文は常に同じ声） | |

- ฉัน・เรา は男女とも使うので手がかりにしない
- ผม は「髪」もあるので文字列一致では見ない。`word_breakdowns` の代名詞（品詞または語義が「私」）に限る。
  ครับ・ค่ะ は紛れないので文字列一致でよい
- 男女の手がかりが両方ある文（引用など）は文末を優先する
- 同じ性別の中でどの声にするかも `thai_text` のハッシュで決める。**ランダムに選ばない**
  （選ぶたびにファイル名が変わるため）
- 単語の部品もその文の話者と同じ声にする
- 判定はサーバー（Go）とクライアント（Dart）の両方に置き、共通のテスト例文で一致を保つ

### 日英：案内役の固定1声

意味・訳は性別に関係なく固定の1声（ja-JP / en-US の Chirp3-HD）。タイ語の話者と声が違うので
「いまは解説」と耳で区別できる。

## 詳細画面の再生

今の `SentenceAudioPlayer` は、頭出しバーで選んだ単語から後ろの文字列を TTS に読み直させている。
時刻は使っておらず、バーの位置は「文字位置 ÷ 全体の文字数」で出している（`wordIndexAtProgress`）。

ファイルにしても同じ考え方をとる。文字の割合 ≒ 時間の割合とみなし、
**頭出し位置 = 単語の先頭の文字位置 ÷ 全体の文字数 × 音声の長さ**。
精度は今と同程度の見込み。ずれが気になれば、単語ファイルの長さの比で割り振る。

Chirp3-HD は SSML の `<mark>` に対する timepoints を返さない（実測で空）。Neural2 は返すが
タイ語は女性1声だけで男女の出し分けができないため採らない。

- 単語タップは、その単語のファイルを鳴らす
- 毎回声をランダムに選ぶ今の挙動（`_pickRandomVoice`）は無くなり、文ごとに声が決まる
- 「ゆっくり」は `speakingRate` 0.7 の別ファイル。再生側の引き伸ばしより自然に聞こえる

## 端末への保持

| 例文 | 扱い |
|---|---|
| お気に入り | 端末に保持。オフラインで再生できる |
| それ以外 | 再生時に取得し、一時キャッシュ（上限20MB程度、古い順に消す） |

- お気に入りにしたら音声一式（約80KB）を落として保持する。一時キャッシュにあれば移すだけ
- お気に入りを外したら一時キャッシュ側へ戻す
- 別端末でお気に入りにした文は、同期で取り込んだときに裏で落とす
- 聞き流しでは、お気に入り以外は次の2〜3文を先読みする

## バックグラウンド再生

ファイルを `just_audio` で鳴らすので、裏に回しても・画面ロック中も鳴り続け、
ロック画面・イヤホンで操作できる（再生／一時停止・前／次の文）。部品間の無音も再生として扱われる。

- iOS：`UIBackgroundModes` に `audio`
- Android：メディア再生のフォアグラウンドサービス（`FOREGROUND_SERVICE_MEDIA_PLAYBACK`）。Play Console で申告
- 次の文が取得できず音が途切れると、iOS はアプリを止めて取得も止まる。先読みを2〜3文にし、
  間に合わない文は飛ばす
- 裏では、サーバー音声がある文だけを流す（端末TTSでの書き出しが裏で動くかは未検証）
- 割り込み：電話・他アプリの音・イヤホンを抜く → 一時停止。アプリ内でお手本再生や
  発音練習（録音）を始めたら聞き流しを一時停止（iOS の AVAudioSession を共有しているため）

## 通信量

Chirp3-HD の MP3 は 32kbps（約4KB/秒）。

| 部品 | 大きさ |
|---|---|
| 全文 | 約8KB |
| 全文ゆっくり | 約11KB |
| 単語6語前後 | 約25KB |
| 意味6語前後 | 約25KB |
| 訳 | 約8KB |
| **1文合計** | **約80KB**（1セット5文で約400KB、毎日1セット×30日で約12MB） |

## タイ語の声（Cloud TTS、`thai-memo-dev` で一覧取得）

| 種類 | 声 |
|---|---|
| Chirp3-HD | 30（女性13・男性17）、24kHz |
| Neural2 | C（女性）1つ |
| Standard | A（女性）1つ |

ja-JP にも Chirp3-HD が30ある。Standard-A と Neural2-C はどの文でも長さが同じで、
読み方の土台は共通らしい。声調の確認は `sentence-quality-audit` の流れに音声チェックを足して行う。

## 検証済みのこと（端末TTSの予備経路）

`flutter_tts` の `synthesizeToFile`（2026-10-19）。

| | iOS シミュレータ | Android エミュレータ（Google TTS） |
|---|---|---|
| 書き出し | タイ語・日本語・英語すべて成功（.caf / .wav） | すべて成功 |
| 形式 | 22.05kHz・Float32・モノラル | 16bit・モノラル。ネット経由の声48kHz、端末内の声24kHz |
| 速さ | 初回3.6秒、以降20〜240ms/部品 | 初回3.3秒、以降10〜450ms/部品 |
| 機内モード | ― | ネット経由の声は待たずに同じ話者の端末内版へ切り替わる |

- サンプルレートは端末内でも混在する。**部品を1ファイルに結合せず**プレイリストに並べるので変換は不要
- Android は `isFullPath: true` を必ず付ける（付けないと共有の Music フォルダに書く）
- iOS は書き出しと発話が同じシンセサイザーを使うので、お手本再生中は書き出せない
- Android の声は `network_required == "0"` に絞る（遅いネットでの待ちを避ける）。
  項目が無いエンジンは端末内扱い。iOS には項目が無いので全部残る
- 未確認：iOS 実機（高品質な声）、遅いネットでの Android、裏での書き出し
